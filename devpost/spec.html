PitchPal: how it's built

The technical blueprint behind your PRD. Canonical version: devpost/spec.md.

How this works, in plain language

PitchPal is a web app that runs entirely inside your browser, on a laptop or phone. There's no server and no database. It's built from three kinds of pieces:

Screens: ReactFive screens (Opening, Home, Practice, Pick a note, Results) built from small reusable components like the dot and the try counter.
Sound engine: Web AudioBuilt into the browser. It plays a soft tone at an exact pitch and listens to the mic many times a second.
Pitch detector: pitchyA free library. For each slice of sound it returns the pitch and a clarity score from 0 to 1.

A slice of sound only counts if it's loud enough and clear enough. PitchPal then compares the pitch to the target, counting the same note an octave lower or higher as a match. Higher puts the dot above the line, lower puts it below, and further off puts it further away. Staying in the zone for 3 seconds counts as a hit. The round and Pick a note share one note engine (tries, hold, Hear it again), so the hard part is written once. Nothing is saved: scores live in memory.

Why this shape: the browser can already play sound, use the mic, and draw screens. A server or database would add pieces to build and break without making the dot any better.

Stack

  • React (current version from Vite, expected 19.x): your choice, to learn React. Tradeoff accepted: installing Node.js once, plus more files. react.dev
  • Vite (expected 7.x): creates, runs and packages the React project. vite.dev
  • Node.js (LTS, 22+): runs Vite on your laptop. It isn't part of the finished app. nodejs.org
  • pitchy (4.x): pitch + clarity. Recommended; you accepted it. GitHub
  • Web Audio API + getUserMedia: built into the browser. MDN docs
  • JavaScript, plain CSS variables, Git + GitHub: implementation details.

Not verified online while writing this: exact versions, Vite's minimum Node version, and pitchy's function names. These get checked in the first build step.

Where it runs and how someone tries it

  • While building: npm install once, then npm run dev → open http://localhost:5173 in Chrome.
  • Online (your choice): Netlify free plan, connected to GitHub. Build npm run build, publish dist. You get an https://…netlify.app link, which phones need before they'll allow the mic. Set up in 6-ship.
  • Required for submission: a short demo video + a public GitHub repo. The link is a bonus; it doesn't replace either one.
  • Demo: Opening → Home → Start → allow mic → listen (note name shown) → sing off so the dot moves → adjust until it turns green and "You nailed it, well done!" appears → finish → results. If there's time: Pick a note.

Where it could break, and what you'll see

  • Mic refused → "PitchPal needs your microphone to hear you sing…" No round starts.
  • Silence or too quiet → dot hidden, "I can't hear you, try singing louder." The try doesn't count.
  • Jittery dot / room noise → smoothing + loudness/clarity cut-offs, tuned on your voice.
  • No sound on a phone → the sound engine only starts inside the Start tap. The Listen cue says "Turn your sound up."
  • App hears its own tone → the mic is ignored while the note plays.
  • Mic left on after leaving → Leave always stops the tone and releases the mic first.

What was simplified

  • A soft electronic tone instead of a piano sound.
  • Fixed notes G3–D4, shuffled each round, instead of choosing your voice range. The octave rule covers deep and high voices.
  • Pick a note offers white keys C4–C5 only, with no sharps or flats.
  • One shared note engine instead of two copies of the try/hold logic.
  • One fixed zone, not one that tightens as you improve.
  • Nothing saved, including the theme and both scores.
  • No routing library: App switches screens itself.

"How does it know I'm singing a note at all?"

Two checks on every slice of sound: loud enough and clear enough (a sung note repeats evenly, noise doesn't), and it has to be in the human-voice range. During the build we'll show loudness, clarity and pitch on screen while you sing in your room, and tune the cut-offs until the dot ignores coughs but follows a held "ahh." We'll tune the zone width (starting at ±0.4 semitone) in the same session.
