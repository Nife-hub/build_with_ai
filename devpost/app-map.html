PitchPal App Map

A one-page guide to how PitchPal fits together: what happens when you sing, where it lives in the code, and where to start when you want to change something.

What PitchPal is

PitchPal plays a note, listens while you sing it back, and shows a dot above or below a line so you can see straight away if you're too high or too low. Hold the note on the line for 3 seconds to nail it. A round is 5 shuffled notes with a score at the end; Pick a note lets you choose any key from C4 to C5. Everything runs in the browser. Nothing is saved and there's no server or account.

The route through the code

You followed this route during the build wrap-up. In your editor, search (Ctrl+Shift+F) for the text in quotes. Line numbers are from this snapshot and may drift.

  1. The heartbeat, src/hooks/useNoteAttempt.js, search const tick (about line 79).
    About 60 times a second it reads the mic with readPitch(), works out how many semitones you are off, moves the dot (setOff), and asks the try rules what happened with attempt.update(heard, now).
  2. The try rules, src/lib/attempt.js, search Waiting for the singer to start (about line 31).
    Decides when a try starts, ends, is a hit, or doesn't count. After a used try, a new one waits for you to pause first, which is why one long breath only uses one try. The timings sit at the top: HOLD_SECONDS, STOP_SECONDS, MAX_SING_SECONDS.
  3. What you see, src/components/NotePanel.jsx, search countdown (about line 38).
    Shows the note name and solfège, "Try 2 of 3", the seconds left, and the message. The message wording lives in messageFor at the bottom of useNoteAttempt.js, where you changed it to "Take a breath and let's try again."

A practice to reuse

Turn "this felt wrong" into a concrete scenario, then into a check.

During the slice 2 learner check, singing one long breath across different notes used up all three tries. That vague feeling became a precise scenario ("sing nonstop for 25 seconds") and a precise rule: a try ends after about 1 second of quiet or 10 seconds of singing, and the next try waits for a pause. Because the try rules live in plain JavaScript (src/lib/attempt.js, separate from React and the microphone), the scenario could be replayed as pretend readings: "one long breath: try 2 waits for a pause" became one of ten automatic checks, alongside the real singing test.

On another project: when something feels off, write down the exact steps that show it, agree what should happen instead, and keep the rule in a small piece of code you can feed made-up input. The bug report then becomes a test that keeps it fixed. The reasoning is recorded in devpost/checklist.md under Revisions.

Run it again

In the project folder: npm install (first time only), then npm run dev, and open http://localhost:5173 in Chrome. Allow the microphone when you press Start.

Testing on a phone

Phones only allow the microphone on a secure https:// page, so the laptop's local address won't work there. Use the deployed site, or a temporary Cloudflare tunnel to http://localhost:5173 (the dev server already accepts .trycloudflare.com addresses). On Android, close chat bubbles, screen filters and floating widgets first, or Android blocks the permission pop-up.
